## Real bugs found and fixed during the build (not hypothetical — hit and fixed)

- Prisma 7 requires an explicit driver adapter for SQLite (`@prisma/adapter-better-sqlite3`);
  the `prisma-client-js` + inline `url` pattern D-003 implicitly assumed no longer
  validates. Switched generators mid-Phase-2 (see commit on `8f5f3eb`).
- Next.js 16 renamed `middleware.ts` → `proxy.ts` (mechanically identical). Caught via
  the dev server's own deprecation warning, not assumed — see D-006/D-009's instruction
  to check current docs rather than trust training data.
- The `proxy(request, event)` Next.js runtime calling convention collided with a
  test-injected `secretOverride` second parameter — silently broke real auth (the event
  object is truthy, so it always won over `process.env.SESSION_SECRET`). Only caught by
  the curl-based end-to-end proof, not by unit tests alone, which is the exact argument
  D-011 makes for verifying against a real artefact instead of trusting a green test
  suite as sufficient proof on its own.
- D-005's average-rating query (`rating: { not: null }` only) doesn't satisfy D-007's
  stricter required test (a stray rating on a PLANNED/READING book must never affect the
  average). Implemented D-007's version (adds `status: FINISHED` to the filter),
  documented in the Books/Dashboard commit rather than silently picking one.
- `revalidatePath` needs a live Next.js request context and throws inside a plain Vitest
  test. Every feature's DB logic was split into a plain `lib/*.ts` module (unit-testable)
  with a thin `"use server"` wrapper in `app/*/actions.ts` that adds `revalidatePath` —
  same shape reused for members, books, and meetings.
